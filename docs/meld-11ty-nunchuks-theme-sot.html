Meld 11ty Nunjucks Documentation Theme

This document defines the documentation theme architecture for Meld. It replaces the rough visual draft with a release-ready source of truth for Eleventy, Nunjucks templates, navigation, Markdown conventions, package imports, and deployment checks.

The file name keeps the original draft spelling, but the implementation and documentation should use Eleventy and Nunjucks.

Package @meldjs/meld
Website https://meldjs.dev
Theme Stack Eleventy, Nunjucks, Markdown, Meld examples

Package Identity

All documentation examples must use the current package identity. Older examples that reference meldjs as an unscoped package are obsolete.

Item Canonical Value Notes
NPM package @meldjs/meld Primary installation path.
JSR package @meldjs/meld Mirror package for JSR publishing.
Website https://meldjs.dev Canonical documentation and landing domain.
Core import import { defineMeld } from '@meldjs/meld'; Use this in application examples.
Plugin import import { MeldRouter } from '@meldjs/meld/plugins/router'; Plugin subpaths map to src/plugins/meld-*.js.

Information Architecture

The docs directory is the source content layer. Eleventy should convert Markdown into static pages and use Nunjucks layouts for chrome, navigation, tables of contents, code blocks, and callouts.

Route Source Purpose Status
/ docs/index.md Project introduction and first runnable component. Required
/installation/ docs/installation.md Install, CDN, local setup, and package manager instructions. Required
/core-api/ docs/core-api.md Core function reference for defineMeld, meldState, computed, meldHtml, lifecycle, and context APIs. Required
/rendering/ docs/rendering.md Template rendering, dynamic values, events, raw HTML, and keyed lists. Required
/plugins/ docs/plugins.md, docs/plugins/*.md Plugin index and individual plugin references. Required
/tooling/ docs/cli.md, docs/editor-setup.md, docs/tooling/*.md Artisan CLI, editor integration, language injection, and local development tooling. Required
/deployment/ docs/deployment.md, docs/releases.md Build outputs, package publishing, CDN usage, and release notes. Required
/integrations/ docs/integrations/*.md Framework, backend, and stack integration guides such as KMEL. Optional

Eleventy Configuration

The theme should use a small Eleventy configuration and avoid a heavy client-side docs app. Meld examples can run inside documentation pages, but the navigation shell should be static and crawlable.

Base Eleventy Config

export default function(eleventyConfig) {
  eleventyConfig.addPassthroughCopy({ 'docs-theme/assets': 'assets' });
  eleventyConfig.addPassthroughCopy({ 'dist/meld': 'vendor/meld' });

  eleventyConfig.addCollection('docs', (collectionApi) => {
    return collectionApi
      .getFilteredByGlob('docs/**/*.md')
      .sort((a, b) => (a.data.order || 999) - (b.data.order || 999));
  });

  eleventyConfig.addFilter('isActiveUrl', (pageUrl, itemUrl) => {
    return pageUrl === itemUrl || pageUrl.startsWith(`${itemUrl}/`);
  });

  return {
    dir: {
      input: 'docs',
      includes: '../docs-theme/_includes',
      data: '../docs-theme/_data',
      output: 'public'
    },
    markdownTemplateEngine: 'njk',
    htmlTemplateEngine: 'njk'
  };
}

Nunjucks Layout Contracts

Layouts should keep the page shell consistent while each Markdown file owns its page title, description, order, and navigation grouping through front matter.

Markdown Front Matter

---
title: Core API
description: Core Meld functions and utility reference.
layout: layouts/docs.njk
section: Reference
order: 30
toc: true
---

Base Layout Requirements

Slot Requirement
head Title, description, canonical URL, theme CSS, and syntax CSS.
header Logo, docs search trigger, theme toggle, GitHub/GitLab links, package version.
sidebar Primary navigation generated from navigation.js.
content Rendered Markdown body with heading anchors and code block controls.
toc Page-level heading list generated from h2 and h3 elements.
footer License, package links, release link, and edit-page link.

Markdown Conventions

The documentation should be consistent enough for readers and automation. Each page must be written as a focused reference, not a loose note dump.

  • Use one h1 per page, supplied by the layout from front matter.
  • Use h2 for major sections and h3 for local reference blocks.
  • Use current package imports: @meldjs/meld and @meldjs/meld/plugins/*.
  • Use runnable code examples. Avoid pseudo-code unless the section explicitly labels it as conceptual.
  • Keep grammar direct: present tense, active voice, and short paragraphs.
  • Prefer "Meld" for the product name and "Meld.js" only where the brand form is needed.
  • Spell framework names correctly: Eleventy, Nunjucks, JavaScript, TypeScript, GitLab, GitHub.

Theme Components

The theme should provide reusable template components for repeated documentation patterns.

Component Template Use
Callout shortcodes/callout.njk Notes, warnings, compatibility details, and security warnings.
Code panel partials/code-panel.njk Syntax-highlighted code with copy buttons and optional tabs.
API table partials/api-table.njk Function, parameter, default, return type, and notes.
Plugin card partials/plugin-card.njk Plugin status, import path, helpers, component tags, and examples.
Package links partials/package-links.njk NPM, JSR, CDN, source repository, and release notes.

Assets and Styles

The theme CSS should be static and small. Meld examples may hydrate inside content, but the docs should remain readable without JavaScript.

  • Use one main stylesheet at /assets/docs.css.
  • Use one progressive-enhancement script at /assets/docs.js.
  • Keep layout widths stable: sidebar, content column, and table of contents should not shift during hydration.
  • Use CSS custom properties for light and dark themes.
  • Keep code block copy buttons and mobile navigation in plain JavaScript.
  • Do not place documentation content inside client-rendered cards. Markdown output must be crawlable HTML.

Search

The first release can use a static search index generated by Eleventy. The index should include title, URL, description, headings, and body excerpts. 

eleventyConfig.addCollection('searchIndex', (collectionApi) => {
  return collectionApi.getFilteredByGlob('docs/**/*.md').map((item) => ({
    title: item.data.title,
    url: item.url,
    description: item.data.description || '',
    section: item.data.section || 'Docs'
  }));
});

Search must degrade gracefully. If JavaScript is disabled, the documentation remains browsable through sidebar navigation and the sitemap.

Workflow

Documentation changes use the same Git discipline as code changes.

  1. Start from develop.
  2. Create a feature branch in a separate worktree, for example feature/docs-11ty-theme-sot.
  3. Make focused documentation and theme changes.
  4. Run docs checks, HTML validation, linting, tests, and production build where applicable.
  5. Commit using Conventional Commits.
  6. Merge the feature branch back into develop after verification.
git worktree add -b feature/docs-11ty-theme-sot ../meldjs-docs-11ty develop
cd ../meldjs-docs-11ty
git commit -m "docs(theme): add Eleventy Nunjucks source of truth"
git switch develop
git merge --no-ff feature/docs-11ty-theme-sot

Acceptance Criteria

  • The docs theme builds from Eleventy without runtime errors.
  • All examples use @meldjs/meld, not the legacy unscoped meldjs package name.
  • Plugin examples use @meldjs/meld/plugins/name.
  • The sidebar, table of contents, and footer are generated from shared data or layout templates.
  • Each Markdown page has front matter with title, description, section, and order.
  • The generated HTML is readable without JavaScript.
  • Dark mode, mobile navigation, and code copy controls work as progressive enhancements.
  • Release docs link to NPM, JSR, CDN, repository, and meldjs.dev.
